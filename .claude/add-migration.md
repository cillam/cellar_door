# Skill: Add a database migration

You write database migrations only when the human asks you to. Before you start, the human should have answered three questions in the PR description: why this can't live in JSONB, whether the change is backward-compatible, and what the rollback path is. If those answers aren't present, ask before proceeding.

This project uses Alembic against Supabase Postgres. Migrations run manually from the developer's machine against the Supabase connection string.

## Steps

### 1. Update the SQLAlchemy model

In `backend/app/db/models.py`, add or modify the column on the `ItemRow` ORM class. Example:

```python
class ItemRow(Base):
    __tablename__ = "items"
    # existing columns...
    last_verified_at: Mapped[datetime | None] = mapped_column(nullable=True)
```

### 2. Autogenerate the migration

From `backend/`:

```
alembic revision --autogenerate -m "add last_verified_at to items"
```

Open the generated file and verify:

- The `upgrade()` does exactly what's intended.
- The `downgrade()` is a real inverse, not a no-op or destructive.
- No spurious changes from out-of-sync models. If autogenerate produced changes you didn't ask for, stop and surface them in the PR — do not commit them.

### 3. Hand-edit if necessary

Common reasons to edit the autogenerated file:

- **Data migration.** Autogenerate only handles schema. If existing rows need backfilling, add `op.execute("UPDATE ...")` between schema changes.
- **Nullable → non-nullable transitions.** Two migrations: first add nullable with a default or backfill, then a second migration to make non-nullable after all rows have values.
- **Index creation on a large table.** Use `op.create_index(..., postgresql_concurrently=True)` to avoid locking. Requires running outside a transaction — note this in the migration docstring.

### 4. Test the migration

```
alembic upgrade head
psql $DATABASE_URL -c "\d items"
alembic downgrade -1
psql $DATABASE_URL -c "\d items"
alembic upgrade head
```

If the downgrade fails or produces a different schema than before the upgrade, the migration is broken. Surface this to the human; do not merge.

### 5. Update affected code

- **Pydantic models.** If the column maps to a BaseItem field, update `backend/app/models/items.py` to match.
- **API responses.** If the new field should appear in `GET /items` responses, update the serializer. If it should not appear (internal-only), confirm it isn't leaked.
- **Mobile types.** Run `openapi-typescript` against the updated FastAPI schema to regenerate mobile API types.
- **Tests.** Add a test that exercises the new column's behavior.

### 6. Run against Supabase

After merging:

```
DATABASE_URL=<supabase-connection-string> alembic upgrade head
```

Supabase has a connection pooler (pgbouncer, port 6543) and a direct connection (port 5432). Migrations must run against the **direct connection (5432)**. DDL through the pooler in transaction mode fails unpredictably.

## Verification before merging

- [ ] Migration has both `upgrade()` and `downgrade()`; both run successfully against local Postgres
- [ ] The downgrade produces a schema identical to the pre-upgrade state
- [ ] Pydantic models updated to match
- [ ] Mobile API types regenerated if the change affects API responses
- [ ] No secrets in the migration file
- [ ] Migration file has a descriptive docstring explaining *why*, not just *what*

## What NOT to do

- **Do not edit a migration that has been applied to Supabase.** Once a migration runs against the real DB, it's immutable. Changes require a new migration.
- **Do not use `alembic revision` without `--autogenerate` unless explicitly asked.** Hand-written migrations from scratch are error-prone.
- **Do not squash migrations.** History is useful.
- **Do not add a new table for category-specific data.** The `items` table handles all categories via JSONB. A new table is a design smell — re-read SPEC.md's schema section before proceeding.
- **Do not drop columns without surfacing the deprecation question to the human.** Old app versions in users' hands still send the old fields.
